## 3. AI 오류 발견과 수정

아래 2건은 **Claude 가 만든 1차 코드의 문제를 Claude 가 검증 보고서와 화면을 검토하다 발견해 고친 것**입니다.

### 오류 #1 — 수량 오류 하나가 가짜 "연결 안 된 품목" 오류를 만듦 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 음수 수량 입력(`qty_negative`)에 대해 `QTY_NOT_POSITIVE` 와 함께 **`ORPHAN_ITEM`(ELB-25A 가 연결 안 됨)** 도 보고됨 |
| 원인 | 수량이 틀린 줄을 연결 그래프에서 통째로 빼버려서, 그 줄의 자식이 최상위에서 도달 불가로 판정됨 |
| 영향 | 도면 담당자가 멀쩡한 연결을 고치려고 시간을 쓰게 됨 (오류 목록을 믿을 수 없게 됨) |
| 왜 처음 검증에서 못 잡았나 | 검증이 "기대 코드가 **포함**되어 있는가"만 봤음 → 부수 오류를 통과시킴 |
| 수정 | ① 부모·자식이 정상인 줄은 수량이 틀려도 연결 관계에 포함 ② 검증을 "기대 코드 **만** 나와야 함"으로 강화 |
| 근거 | `test_bad_qty_does_not_create_false_orphan`, `reports/quantity_verification.md` 오류 입력 표 |

### 오류 #2 — m 단위 보기에서 판 두께가 0.008m 로 표시됨 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 화면 캡처 검토 중 `PL-SHELL t0.008m` 표시 발견 |
| 원인 | 단위 전환을 길이·두께 구분 없이 모든 치수에 적용 |
| 판단 | 계산은 맞지만, 현장에서 판 두께는 항상 mm(6t, 8t)로 말하므로 혼란을 준다 |
| 수정 | 두께는 항상 mm(`thickness_mm`). 단위 전환은 배관·봉재 길이에만 적용 |
| 근거 | `test_thickness_always_mm`, `reports/screen_bom_D.png` |

## 4. 정답 데이터를 코드와 독립적으로 만든 방법
`fixtures/expected.json` 의 전개 수량은 코드를 돌려서 얻은 값이 아니다. 파일 안의 `_계산` 항목처럼
"쉘 1 × 노즐 3 × 볼트 4 = 12" 같은 식으로 **손으로 계산**했다. 그래서 코드와 정답이 일치한다는 것이 의미가 있다.
