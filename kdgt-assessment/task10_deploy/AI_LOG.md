## 2. 프롬프트 기록

### Claude — 1차 구현
- 입력: 과제 슬라이드 10 원문 + "10부터 하자"
- 선택 과제: 06 (쓰기·조회 모두 있어 권한 시험에 적합), LLM 시간초과용으로 07 질의응답 추가
- 결과: 커밋 "과제 10 …"

### 검토 방식
- 같은 시나리오를 로컬 프로세스와 **실제 Docker 컨테이너**에서 모두 실행
- 시나리오가 통과해도 감사 로그 상태코드 분포·응답 시간을 다시 읽음 → 아래 오류 2건 발견
- 사용자 검토: (직접 기입 — `demo.sh` 녹화 시 확인한 내용)

## 3. AI 오류 발견과 수정

### 오류 #1 — 감사 로그가 실제 응답과 다른 상태코드(500)를 기록 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 시나리오는 전부 통과했는데 감사 로그 상태코드 목록에 500 이 있었음 |
| 원인 | 감사 래퍼가 과제 03 의 오류 클래스(BomError)만 잡았다. 과제 06 의 업무 오류(DomainError)는 클라이언트에는 409 로 정상 응답됐지만 감사 로그에는 500 으로 남음 (13건) |
| 영향 | 사고 조사 때 감사 로그를 믿을 수 없음 (없던 서버 오류가 있었던 것처럼 보임) |
| 수정 | `http_status` 를 가진 모든 예외에서 상태코드를 기록. 검증에 "감사 로그에 예상치 못한 500 없음, 409 는 409 로" 항목 추가 |

### 오류 #2 — LLM 제한 3초인데 첫 요청은 4.8초 만에 504 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 검증 기준(제한+3초)은 통과했지만 첫 요청만 1.8초 초과 |
| 원인 | 첫 요청 때 Agent 생성(SDK 로딩, 질의응답 DB 생성)이 시간 제한 바깥에서 일어남 |
| 수정 | 기동 시 백그라운드로 Agent 미리 준비 → 모든 요청 3.01초. 검증 기준도 '제한+1초'로 강화 |

### 설계 중 바로잡은 점
- 운영 연결을 `mode=rw` 로 열도록 함: 기존 연결 함수는 DB 파일이 없으면 빈 DB 를 새로 만들어, 볼륨이 빠진 장애가 '데이터 0건'으로 조용히 숨겨질 수 있었다
- 프록시 CA 는 BuildKit secret 으로만 넘겨 이미지에 남지 않게 함(이미지 안에서 인증서 파일 없음 확인)
