## 2. 프롬프트 기록

### Claude — 1차 구현
- 입력: 과제 슬라이드 05 원문 + "과제 05 진행해줘"
- 결과: 커밋 "과제 05 …" (git log 참고)

### 검토 방식
- 모델 선택은 검증셋으로만 하고, 테스트 정답을 바꿔도 선택이 같은지 테스트(`test_model_selection_ignores_test_targets`)
- 잘못된 분할(무작위)로 일부러 평가해 누수가 성능을 얼마나 부풀리는지 비교
- 큰 오차 표를 사람이 읽고 원인 태그를 확인
- 사용자 검토: (직접 기입 — 생성 규칙이 현장 원가 구조와 비슷한지, 한계 보고서의 결론에 동의하는지)

## 3. AI 오류 발견과 수정

### 오류 #1 — 신뢰구간을 행 단위로 계산해 실제보다 좁게 보고함 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 처음 보고서는 선택 모델의 기준선 대비 개선 구간을 **+2.1 ~ +9.7%p** 로 보고 |
| 발견 | 큰 오차 표에 같은 프로젝트(PJ110 ×3, PJ056 ×2, PJ089 ×2)가 반복해서 나타남 → 재견적끼리 오차가 함께 움직임 |
| 원인 | 붓스트랩을 행(39건) 단위로 해서, 서로 독립이 아닌 재견적을 독립 표본처럼 취급 |
| 수정 | 프로젝트(19개) 단위 붓스트랩으로 변경 → 개선 구간 **+0.3 ~ +11.1%p** (0 을 겨우 벗어남). GBM 직접 예측은 구간이 0 을 포함하므로 "기준선보다 낫다고 말할 수 없음"으로 결론 수정 |
| 근거 | `test_cluster_bootstrap_wider_than_row_bootstrap`, `reports/metrics.md` |
| 의미 | "같은 프로젝트를 분할에 섞지 않는다"는 원칙은 분할뿐 아니라 **불확실성 계산**에도 적용해야 한다 |
