## 2. 프롬프트 기록

### Claude — 1차 구현
- 입력: 과제 슬라이드 08 원문 + "과제 08 진행해줘"
- 결과: 커밋 "과제 08 …"

### 검토 방식
- 같은 이벤트 집합을 무작위 순서로 넣어 상태가 같은지(순서 독립) 확인, 도착 순서대로 계산하는 방식과 비교
- 현황판 캡처를 읽고 화면 안의 모순(공정 순서와 상태)을 찾음
- 사용자 검토: (직접 기입)

## 3. AI 오류 발견과 수정

### 오류 #1 — 계획을 실제 진행으로 만들어 지연이 보이지 않을 뻔함 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 처음 시뮬레이터는 작업이 다음날 04:15 까지 이어졌고, 계획 시작시각이 설비의 '실제' 빈 시각으로 정해짐 |
| 원인 | 계획과 실적을 한 반복문에서 같이 만들어, 계획이 실제 지연을 흡수함 → 대시보드의 '지연'이 거의 0 으로 나왔을 것 |
| 수정 | 계획(계획 작업시간)을 먼저 고정 → 실제는 늦은 시작·편차·알람으로 따로 시뮬레이션. 작업이 근무시간 안에 끝나는지 assert 추가 |
| 결과 | 계획 종료 16:48, 실제 18:00 → 공정별 지연이 다음 공정·다음 작업지시로 전파되는 모습이 보임 |

### 오류 #2 — 후공정이 끝났는데 선공정을 '대기·시작 지연 459분'으로 표시 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 복구 전 화면에서 WO-008 용접(WELD-02)이 '대기·지연 459분'인데 같은 작업의 검사는 '완료' |
| 원인 | 통신이 끊긴 WELD-02 의 이벤트가 안 와서 '시작 안 함'으로 판단. 물리적으로는 용접 없이 검사가 끝날 수 없음 |

| 수정 | 같은 작업지시의 후공정이 이미 시작됐는데 이 공정 기록이 없으면 상태 '미확인' + "기록 미수신 의심", 지연 0 |
