# 과제 08 — 공정 이벤트 수집과 가시화

> 가공(레이저)·용접·검사 설비의 이벤트를 수집해 공정 상태와 지연을 보여 준다.
> 중복·역순·통신 단절이 있어도 **재전송 후 수량이 정답과 일치**하고, **같은 이벤트를 두 번 세지 않으며**, **도착 순서와 관계없이 같은 상태**가 나온다.

## 설계

| 문제 | 해결 |
|---|---|
| 같은 이벤트가 두 번 옴 | 설비가 붙인 `event_id` 를 기본키로 → 같은 내용은 '중복 무시', 같은 id 에 다른 내용은 '충돌'로 거부 |
| 수량을 두 번 셈 | 수량은 COUNT 이벤트의 **증가분**. 저장이 한 번뿐이므로 합계도 한 번 |
| 늦게 온 이벤트가 상태를 되돌림 | 상태는 도착 순서가 아니라 **발생시각 순으로 다시 재생**해 계산 → 받은 이벤트 집합이 같으면 상태도 같음 |
| 끊긴 걸 어떻게 아나 | ① 마지막 수신 후 15분 무소식 → 미수신 ② 설비별 일련번호(seq)의 빈 번호 → 누락 구간 표시 |
| 후공정은 끝났는데 선공정 기록이 없음 | '대기·지연'이 아니라 **'미확인(기록 미수신 의심)'** 으로 표시 (AI_LOG 오류 #2) |
| 과거 화면 재현 | 상태는 "기준 시각까지 **수신된** 이벤트"로 계산 → 복구 후에 다시 봐도 복구 전 화면 그대로 |
