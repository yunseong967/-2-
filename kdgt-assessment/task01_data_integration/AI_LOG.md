## 3. AI 오류 발견과 직접 수정

### 오류 #1 — 입고 없는 LOT의 검사를 "날짜오류"로 잘못 분류 (수정 완료)

| 항목 | 내용 |
|---|---|
| 문제 | 등록된 LOT 이지만 정상 입고 기록이 없는 상태에서 검사 행이 들어오면, Claude가 작성한 1차 코드는 `DATE_SEQUENCE`(날짜오류)로 격리했다. |
| 왜 문제인가 | 실제 원인은 날짜가 아니라 **검사→입고 관계가 끊긴 것**이다. 그 결과 ① 오류 보고서 분류가 "날짜오류"로 틀리게 집계되고 ② 완료 기준인 "관계가 끊긴 행 조회"(`v_broken_relations`)에서 **이 행이 조회되지 않았다.** |
| 발견 경위 | Claude가 1차 구현 후 자체 검토에서 약점 후보로 기록 → 사용자가 수정을 지시. |
| 재현 | `test_inspection_on_lot_without_receipt_is_broken_relation` 를 먼저 추가 → 수정 전 실패: `AssertionError: assert 'DATE_SEQUENCE' == 'NO_RECEIPT'` |
| 수정 | ① 오류 코드 `NO_RECEIPT`(분류 "입고 없는 검사") 신설 ② `_check_inspection_after_receipt` 가 이 코드를 반환 ③ `v_broken_relations` 조건에 `NO_RECEIPT` 추가 |
| 함께 고친 잠복 문제 | 뷰를 `CREATE VIEW IF NOT EXISTS` 로 만들어서, **이미 만들어진 DB에는 바뀐 뷰 정의가 반영되지 않는** 문제가 있었다 → `DROP VIEW IF EXISTS` 후 재생성으로 변경 |
| 검증 | 테스트 23개 전부 통과, `cli verify` 7개 항목 PASS 유지 (샘플 데이터에는 이 사례가 없어 보고서 수치 변화 없음) |
| 근거 커밋 | `git log --oneline -- kdgt-assessment/task01_data_integration` 에서 "오류 #1" 커밋 |

> 시연 때 설명 포인트: "날짜 검사 함수 안에 관계 검사가 섞여 있어서 분류가 틀렸고, 그 결과 완료 기준(관계 단절 조회)에서 빠지는 행이 생겼다. 실패 테스트로 먼저 재현한 뒤 고쳤다."

남은 검토 후보 (미수정):
- 격리 테이블 유일키가 파일명 기준이라 다른 폴더의 같은 이름 파일을 같은 출처로 봄
- 출하 수량이 수주 수량을 넘는지 검사하지 않음
- CSV 헤더에 필수 컬럼이 아예 없으면 파일 전체가 행 단위 `MISSING_FIELD`로 격리됨 (파일 단위로 즉시 거부하는 편이 나을 수 있음)
