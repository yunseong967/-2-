## 1. 도구별 역할

| 도구 | 모델·버전 | 역할 | 소요시간 |
|---|---|---|---|
| Claude (Claude Code) | (직접 기입) | 정답 설계, 도면 생성, 벡터·스캔·DXF 추출, 교차 검증, 평가·홀드아웃, 오류 분석 | (직접 기입) |

## 2. 프롬프트 기록

### Claude — 1차 구현
- 입력: 과제 슬라이드 02 원문 + "진행시켜"
- 순서: **정답 JSON 커밋(99a4d29) → 도면 생성 → 추출기** (정답이 추출기에 맞춰지지 않게)
- OCR(tesseract 5.3.4 kor/eng), OpenCV, 나눔 폰트를 이 환경에 설치해 사용

### 검토 방식
- 개발용 10장 정확도는 낙관적이라 보고, **개발 중 보지 않은 홀드아웃 10장**을 만들어 결과를 본 뒤 수정 없이 보고
- 사용자 검토: (직접 기입 — 실제 회사 도면 1~2장으로 시험해 본 결과 등)

## 3. AI 오류 발견과 수정

### 오류 #1 — 스캔 도면을 거의 못 읽음: 외형 미검출·표제란 OCR 실패 (수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | 스캔 5장 35필드 중 정답 2개 (나머지 검토) |
| 원인 | ① 홀 지시선이 외형 테두리를 가로질러 윤곽이 사각형으로 근사되지 않음 ② 페이지 전체 OCR 에서 표 격자선이 글자를 방해 |
| 수정 | 외형·표제란 칸을 '선으로 둘러싸인 흰 영역'으로 찾고, 필요한 칸만 잘라 OCR |

### 오류 #2 — 스캔 1장에 17초 (수정 완료)
원인은 OCR 이 아니라 `pdftoppm` 으로 스캔 PDF 를 300dpi 로 다시 그리는 단계(13.5초). 프로파일러로 확인 → 내장 JPEG 를 `pdfimages` 로 꺼내 크기만 맞추도록 변경 → 장당 약 3초.

### 오류 #3 — 기울기 보정이 도면을 90° 돌림 (수정 완료)
OpenCV 5 의 `minAreaRect` 각도 범위가 4.x 와 달라(−90~0) 정규화가 한쪽만 처리 → −89.4° 회전. 양쪽 모두 (−45, 45] 로 정규화. `test_deskew_handles_both_signs`.

### 오류 #4 — 지시선이 붙은 홀 하나를 놓침 (수정 완료, 교차 검증이 먼저 잡음)
원 테두리 윤곽이 지시선과 합쳐져 원형도 판정에서 빠짐 → '지시 8개 ≠ 원 7개'로 검토 처리됨(오답은 아님). 원 내부 흰 영역으로 검출하도록 변경.

### 남은 오류 (수정하지 않고 기록)
- D09 품번 `COVER-01` → `COVER-O1` (0/O 혼동): 품번을 임의로 고치는 건 추측이라 하지 않고, **품번 마스터 대조**로 검토 필요 + 후보 제안
- 홀드아웃 H07: 라벨 오인식으로 다른 행을 잡음(형식 검사가 우연히 막음) → 개선 과제 (오류 분석 E3)
