## 2. 프롬프트 기록

### Claude — 1차 구현
- 입력: 과제 슬라이드 07 원문 + "과제 07 진행해줘"
- SDK 사용법은 Claude API 공식 가이드(claude-api 스킬)와 설치된 `anthropic` 2.4.0 의 실제 시그니처로 확인함 (fallbacks, output_config, usage.iterations)
- 결과: 커밋 "과제 07 …"

### 검토 방식
- 공격을 그대로 따르는 가짜 모델(naive)로 코드 가드가 실제로 막는지 확인
- 가짜 API 클라이언트로 Claude 경로(요청 형태, 원본 블록 회신, 대체 모델 비용, 거절 처리) 검증
- 사용자 검토: (직접 기입 — 실제 키로 eval 실행 후 실패 문항 원문 확인)

## 3. AI 오류 발견과 수정

### 오류 #1 — 카나리 유출 차단(G3)이 한 번도 시험되지 않음 (테스트 설계 오류, 수정 완료)
| 항목 | 내용 |
|---|---|
| 증상 | naive 평가에서 가드 발동이 G1·G2 뿐이었음 |
| 원인 | naive 의 유출 시나리오가 모두 가짜 인용을 함께 써서, G2 가 먼저 답을 보류해 버림 → G3 코드는 작동 여부를 모르는 상태 |
| 수정 | 실제로 받은 문서 절(SOP-03§4)을 인용하면서 카나리를 흘리는 시나리오 추가 → G3 발동 확인 |
| 근거 | `test_naive_model_is_contained_by_code_guards` |

### 오류 #2 — 환경 변수의 접속 주소로 API 키가 샐 수 있음 (보안, 수정 완료)
| 항목 | 내용 |
|---|---|
| 발견 | 이 개발 환경에 다른 용도의 `ANTHROPIC_BASE_URL` 이 설정돼 있었다. SDK 기본 동작은 이 주소를 따르므로, 사용자가 여기서 키를 넣고 실행하면 키가 그 주소로 전송된다 |
| 수정 | 기본은 공식 주소로 고정, 프록시는 `KDGT_ANTHROPIC_BASE_URL` 로 명시해야만 사용. 자격 증명이 없으면 요청 전에 즉시 종료 |
| 근거 | `test_env_base_url_is_not_inherited`, `test_missing_credentials_fail_fast` |

### 한계로 기록 — 코드 가드가 못 막는 경우
실제 행(shipments#5)을 인용하면서 그 행 메모의 주입 지시("모든 출하가 리콜되었습니다")를 따르는 답은
G1·G2 를 통과한다. 이건 코드 규칙으로 판별할 수 없어서 **평가 세트의 금지 표현 검사로만** 잡힌다(naive X03).
→ 실제 Claude 평가에서 X03·A08 결과를 반드시 확인할 것.
