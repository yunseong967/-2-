# 과제 04 — 근거를 보여주는 자동 견적

> 과제 03 의 BOM 전개 수량으로 **재료비·가공비·외주비**를 계산해 Excel 견적서를 만든다.
> 금액마다 **계산식·단가·단가표 버전·출처**가 붙어 있고, 단가가 바뀌어도 이미 낸 견적은 그대로 유지된다.

## 실행 (kdgt-assessment 폴더에서)

```bash
pip install -r requirements.txt                 # openpyxl
python -m task04_auto_quote.cli verify          # 자동 검증 + 견적 Excel 10개 → reports/quotes/
python -m task04_auto_quote.cli demo            # out/task04.db 에 BOM·단가·견적 10건
python -m task04_auto_quote.cli show Q04        # 견적 1건의 줄별 계산식 출력
python -m task04_auto_quote.cli serve           # http://127.0.0.1:8004 API
python -m task04_auto_quote.cli answers         # 독립 계산기로 정답 다시 계산
```

## 계산 규칙 R1

| 항목 | 규칙 |
|---|---|
| 판재 중량 | 가로 × 세로 × 두께(mm) × 비중 ÷ 1,000,000 → **소수 둘째 자리 반올림** |
| 비중 | SUS304 7.93 / SUS316L 7.98 / SS400 7.85 g/cm³ |
| 수율 | 판재 0.85, 길이재 0.95 → 필요량 = 사용량 ÷ 수율 |
| 재료비 | 판재 = 수량 × 중량 ÷ 수율 × kg단가 / 길이재 = 총길이(m) ÷ 수율 × m단가 / 구매품 = 수량 × 단가 |
| 가공비 | 품목 1개당 공정 시간 × 품목 총수량 × 시간당 요율 |
| 외주비 | 품목 1개당 외주 수량 × 품목 총수량 × 외주 단가 |
| 반올림 | 각 줄 금액을 원 단위로 **사사오입**(ROUND_HALF_UP)한 뒤 합산 |
| 공급가액 | 소계에서 천원 미만 절사 |
| 부가세 | 공급가액 × 10%, 원 미만 절사 |
| 단가 선택 | 견적일 기준으로 유효한(적용 시작일 ≤ 견적일) 최신 버전 |

### 손 계산 예 (Q01, 쉘 판 PL-SHELL, 개정 A)
```
1장 중량 = 1260 × 1000 × 6 × 7.93 ÷ 1,000,000 = 59.9508 → 59.95 kg
재료비   = 2장 × 59.95 ÷ 0.85 × 4,800 = 677,082.35 → 677,082원
```
엔진과 독립 계산기 모두 677,082원이다(`test_hand_calculated_line`).

## 정답을 어떻게 믿을 수 있나

정답(`fixtures/expected.json`)은 견적 엔진이 아니라 **`reference_calc.py`** 가 만든다. 이 계산기는
- BOM 원본 JSON 을 직접 읽어 자체적으로 전개하고(과제 03 코드 미사용)
- `Decimal` 대신 `fractions.Fraction` 으로 계산하며
- 규칙을 README 문장을 보고 다시 구현했다.

두 구현이 10건(줄 323개)에서 일치하고, 정답 세트 밖의 조합 5개(수량 1~9, 날짜 경계)에서도 일치한다(`test_engine_matches_independent_calculator_beyond_answer_set`). 여기에 위의 손 계산 1줄을 더했다.

## 알려진 한계

- 판재는 직사각형 블랭크로 계산한다(원형 경판도 사각 블랭크). 실제 네스팅(배치) 수율은 반영하지 않는다
- 일반관리비·이윤은 넣지 않았다(슬라이드 범위는 재료·가공·외주). 넣는다면 규칙 R2 로 추가한다
- 부품 치수(`part_specs.json`)는 과제 02 도면 추출이 완성되면 그 결과로 대체한다
- 견적 정확도 80%(사업 목표)와 이 과제의 "계산 일치"는 다른 기준이다(슬라이드 16)
